# Agent Note：连接器下载入口——用户在浏览器里登记自己的机器

Status: implemented

[English](2026-08-26-connector-download-portal.md) | 中文

## 问题

[connector 执行世界决策](2026-08-26-connector-execution-world.zh.md)让目标机器变得可达，但只对同时掌控两端的运维方成立。把一台机器接入回路意味着：在目标机上安装该包、想一个 token、以 loopback 绑定启动 `dsh-connector-agent`、再从 harness 到那个端口安排 `ssh -L` 隧道或一条私有路由，然后把一条 `dsh-connector-tcp` 声明写进部署的 `cordis.yml` 并重启。其中每一步都预设了对 harness 宿主机的 shell 访问，以及一条通向目标机的入站路径。

对产品用户真正想连接的那台机器来说，这个形状是错的：那是他们自己的笔记本或工作站，处在 NAT 之后，没有固定地址、没有入站端口，也不愿意去编辑某个部署的 YAML。对部署来说同样是错的：它必须重启才能知道有这么一台目标机，而且无法判断配置里点名的机器此刻是否还活着。

产品需求更窄也更锋利：Web UI 里一个看得见的入口、Linux 与 Windows 各一份真实可下载的产物，以及一条从下载到已连接、可验证的连接器的路径，用户步骤要少到安全模型允许的极限。

## 决策

由部署把一段已经写好自己地址的脚本交给目标机，再由**目标机主动拨入**。四项选择支撑起这一点。

**接入方向被反转，走浏览器已经在用的那个源上的 HTTP 升级。** `dsh-connector-agent --attach <url>` 为 `dsh-connector` 协议发起升级请求，并在自己打开的这条 socket 上被服务。此时目标机只需要出站 HTTP：没有入站端口、没有隧道、没有 DNS 名称、不用改路由器。复用部署既有的源而不是另开一个端口，意味着挡在 Web UI 前面的反向代理、TLS 证书与鉴权同样挡在它前面；而其中的代理，正是运维方否则就得配置第二遍的那一件。

协议本身不变。agent 在升级请求中出示自己的登记 token，因此部署在接受任何一个协议字节之前就知道是哪条登记记录拨了进来；随后部署发送携带同一份密钥的同一个 `hello`，agent 以 `ready` 应答，与在被拨 socket 上完全一致。两个方向依然都经过认证，所服务的世界逐字节相同——这正是 `openConnectorLinkOverSocket` 对两种传输是同一条代码路径的原因。

**产物是一段生成的脚本，而不是压缩包。** 目标机需要三个事实——往哪拨、出示哪个密钥、去哪取 agent——而一段脚本把三者装进用户可以直接运行的那一个文件里，且 `curl … | bash` 与下载按钮抓到的是完全相同的字节。压缩包只会给用户的步骤加上解压、给我们的代码加上一个 zip 写入器，而这三个事实一个也不需要。脚本从同一个部署抓取 agent，因此目标机只需要 Node，别的都不需要：不用访问 registry、不用构建、没有 `node_modules`。

这要求 agent 是单个文件。`pnpm run build` 产出 `lib/agent-bundle.js`；由于原生模块无法装进单个文件，该 bundle 把 `node-pty` 与 `koffi` 解析到构建期的桩模块，被调用时即抛错。后果被精确地圈定：该 bundle 完整提供文件系统与一次性命令，失去的是 PTY 分配——本来也不在连接器操作集内——以及只被终端拉起使用的 Windows 进程检查器。

**不可猜测的下载路径就是凭据，而铸出它的 Remote 才是需要鉴权的那个面。** `GET <basePath>/pack/<enrollmentId>` 的唯一门禁就是路径中那 24 字节的 id，因为在下载前再加一道栅栏，等于在一个本不该知道 Web 面鉴权的包里把它复制一遍。鉴权留在它本来就在的地方：`issue` 是经由已鉴权网关的 Typert Remote 调用，因此只有已经在里面的浏览器才能铸出登记记录。

**登记把两种生命周期分开。** pack 下载会过期——文件里带着密钥，而遗留在 shell 历史里的过期链接才是现实中的泄漏面——它授权的接入则不会，因此一台一直在跑的目标机器能熬过笔记本休眠与网络切换，不必重新下载。每次准入的接入都持有一个代号，于是某次接管若在更晚的拨入被准入之后、或在登记记录被吊销之后才完成握手，它会关掉自己的 link，而不去占用在线 agent 持有的槽位。

**登记、渲染 pack 与接入同属一个包。** 它们是同一件事的三个时刻：为下载铸出的密钥就是 agent 出示的密钥，它指向的登记记录就是注册进 `ctx.connectors` 的连接器 id。拆开只会把该密钥摊到多个包的接口上，也换不来任何独立演进的角色，因此 `dsh-host-connector-portal` 同时拥有这三者与 `connectorPortal` Remote，浏览器一侧则是唯一的客户端包 `dsh-client-ui-settings-connectors`。

## 影响

挂载本入口的部署即接受：任何能触及其已鉴权浏览器面的人都能登记一台机器，任何在 pack 过期前拿到它的人都能接入一台。两者都源自连接器本身是什么：对目标机完整的读、写与执行权限，由掌控该部署的人行使。生成的脚本在自己的文件头里就说明了这一点，用户运行前读到的就是这段话，包的 README 则承载威胁模型。

反向接入没有消除传输问题，只是挪动了它。在 `http:` 之下，token 与每一帧都以明文传输，因此可达范围超出私有网络的部署要在入口前终结 TLS——这与它的 Web UI 本就需要的是同一道栅栏。listen 模式的 loopback 默认值与隧道指引原封不动；没有任何东西会隐式放宽某个绑定。

账本在内存中。harness 重启会丢弃全部登记记录，此后每个 agent 的重试循环都会报告接入被拒，直到用户签发新的 pack。这是诚实的失败方式：一台继续服务着某个已不知情部署的目标机器，比一台明说自己被拒绝的更糟。

有两个跨仓库的事实发生了变化。`socket.setEncoding` 从 `dsh-connector-tcp` 与 `dsh-connector-host` 中双双移除，改为在数据处理器里用 `StringDecoder`，因为 Node 禁止改变由 HTTP 请求升级而来的 socket 的编码，而该解码器保留了那次调用原本提供的多字节安全的边界处理。另外，`dsh-connector` 现在拥有升级协议名与那两个请求头，因为反向握手的两端都要读它们。

## 验证

各包的测试固定住：登记账本的四种生命周期状态、其常量时间密钥比较、允许再次拨入替换自身连接的容量核算，以及重新准入与移除时的代号递增；两个族的 pack 渲染，包括在origin抵达 shell 脚本之前就拒掉任何超出 scheme 与 authority 的内容的校验；以及从转发头推导源。

入口自身的测试对真实 webserver 发起真实 HTTP：pack 下载及其过期、agent 程序路由（含其有文档的 `503`），以及在裸 socket 上完成客户端库造不出的那些 attach 升级场景——缺失 `Host`、省略 token 头、协议字节随升级 head 一同抵达、首帧不对、握手中途被吊销，以及两个 agent 争抢同一条登记记录（代号守卫正是让最新者胜出的东西）。agent 的重试循环则针对带 body 与不带 body 的拒绝、传输错误，以及拨号中途的取消进行验证。

在测试套件之外，整条路径已针对本地组装的 Web 应用端到端跑通：经网关 `issue`、下载、运行脚本，并通过由此得到的连接器 link 读到目标机上的真实文件；随后吊销，确认 agent 被断开且再次拨入被拒。

## 已考虑的备选方案

**保留 listen 模式，在 UI 里给出隧道说明。** 否决，因为它不满足需求。剩下的每一步——安装、隧道、YAML、重启——都还在，而对产品用户最难的那两步，入站路径与部署重启，恰恰是反向拨入所消除的。

**提供包含 agent 与启动脚本的 zip 或 tarball。** 按删除测试否决：压缩包给用户加了一步解压、给我们加了一个归档写入器，却没承载脚本尚未承载的任何事实。

**为每个平台提供编译后的单文件可执行程序（`node --experimental-sea-config` 之类）。** 暂缓。它能免掉 Node 前置条件，但需要各平台的构建机、macOS 与 Windows 上的签名，以及会把单行安装拖成慢速下载的分发体积。对本方案面向的这些机器而言，要求 Node 22 是更小的代价。

**把 token 放进下载 URL 的 query 而不是 path。** 否决，因为 query 被各类代理记录的频率远高于 path，而这个 path 段本就不可猜测。

**直接为下载路由鉴权，复用 API 网关的信任栅栏。** 否决，因为该栅栏属于客户端连接包，而跨那道 seam 引入另一个插件的符号并不是宿主包可以做的事。通过已鉴权的 Remote 铸出 id，等于把检查放回它本来就在的地方。

**在本页面把会话绑定到某个连接器。** 暂缓而非否决。页面会给出每台已接入机器的连接器 id，会话则通过挂载连接器版 provider 的 agent preset 抵达它。为每场对话挑选目标是 preset 组合的问题，属于 agent-preset UI，而不属于登记。

**持久化登记账本。** 暂缓。它需要一个存储、一套能熬过重启的吊销方案，以及对“一份 pack 跨越重新部署仍然有效”意味着什么的判断。在部署提出更大的需求之前，内存记录加上可见的拒绝，是更小的正确答案。
